  - Reads of entity A's rows in all 13 data tables, as each of 8 identities: owner, editor, viewer,
    inactive member, signed-in non-member, owner of entity B, anon and service_role (104 checks).
    schema_migrations is refused to all 8.
  - A signed-in non-member sees zero rows in every table. Owner of A and owner of B each see exactly
    their own entity's rows.
  - 49 write statements (insert, update, remove on every table, plus parent-key moves, protected
    columns, status changes), each tried as all 8 identities and undone (392 checks).
  - Cross-entity: A against B's rows; a user who belongs to both cannot mix entities (composite keys,
    same-plan trigger); deactivated and reactivated members.
  - Helpers: lookups executable by no API role; membership helpers authenticated-only, boolean,
    SECURITY DEFINER STABLE with a fixed search_path; nothing executable by PUBLIC; every callable
    function refused to anon and service_role.
  - create_entity: no user id refused; bad inputs refused; the cap of 10 owned entities with its
    exact message; a failure in the last step undoes everything; the per-user advisory lock is held
    until commit.
  - Member functions: editors, viewers and other entities' owners refused; the last owner cannot step
    down or deactivate.
  - Locked versions refuse changes to lines, scenarios, values, packs, name and removal, and can be
    unlocked.
  - Constraints: duplicate actuals, entity/connection mismatch, non-month periods, every enumeration,
    actual lines with an amount, overflow beyond numeric(14,2), unverified rules without a source,
    a DRAFT filename in schema_migrations.
  - Structure: row security on all 14 tables, an updated_at trigger on every table, no foreign key
    out of fpa, no float or money columns.
