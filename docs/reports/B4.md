## What was built

### Auth: shared Clerk instance, Klaro's own redirects (`src/app/auth.tsx`, `src/lib/clerk.ts`)

The instance's dashboard defaults (home, after sign-in, after sign-up) all point at `app.ledgrly.ie`.
Klaro relies on none of them.

- **ClerkProvider** is mounted inside the router and navigates with react-router, as Ledgrly does.
  It is given every path explicitly:

  | Setting | Value |
  |---|---|
  | `signInUrl` | `/sign-in` |
  | `signUpUrl` | `/sign-up` |
  | `signInFallbackRedirectUrl` | `/` |
  | `signUpFallbackRedirectUrl` | `/` |
  | `afterSignOutUrl` | `/sign-in` |
  | `allowedRedirectOrigins` | Klaro's own origin only |

- **Sign-in** is the embedded `<SignIn>` on Klaro's own `/sign-in` page.
  - Where the user goes next comes from Klaro's own `?return=` parameter, not Clerk's `redirect_url`.
  - That value is checked by `safeReturnPath`: it must be a path on Klaro's origin.
    - Not accepted: `//host`, `/\host`, schemes, control characters, or a path back into sign-in or sign-up.
    - Anything else becomes `/`.
  - It is then passed to Clerk as `forceRedirectUrl`, so Clerk can't send the user anywhere else.
- **Sign-up** is the embedded `<SignUp>` on `/sign-up`.
  - It is for invitation links only, because the instance is invite-only.
  - It says so on the page.
- **Sign-out** is Klaro's own button. It calls `signOut({ redirectUrl: '/sign-in' })` and shows an
  error if sign-out fails.
- **Protected routes** (`RequireAuth`):
  - A signed-out user goes to `/sign-in?return=<where they were>`.
  - Nothing below renders until the Supabase client holds the user's Clerk token. A test checks
    the token is set before the first data read.
- **If Clerk cannot start**, the page says "Sign-in could not start", instead of waiting forever
  on "Checking your sign-in…".
  - Fail closed. I found this live on localhost (below).

### Data access (`src/features/entities/api.ts`, `src/lib/useLoad.ts`)

- **Supabase client:** default schema `fpa`, with the Clerk token sent as the access token (as in
  Ledgrly and Trinity).
- **All reads go through `src/lib/db.ts`:**
  - `must()` and `mustMaybe()` throw on any error.
  - The entity list asks for an explicit range (0–199) and throws if the page comes back full, so it
    never relies on the default row limit.
- **`useLoad`** is the one loading hook. Its state is loading, error (with the message shown) or ok;
  an error never looks like an empty list. A late reply for a previous entity is dropped.
- **`createEntity`** calls `fpa.create_entity` with exactly `p_name`, `p_jurisdiction`, `p_currency`
  and `p_fiscal_year_start`.
  - Database errors are shown as written (for example the PT429 cap message).
  - A reply without a uuid counts as an error.

### Entity model

- **Routes:**
  - `/`: the last entity this user opened (remembered per Clerk user, and only if still a member),
    else the first, else the create form.
  - `/entities`: the list.
  - `/entities/new`: the create form. It asks for name, jurisdiction IE/UK, currency EUR/GBP and
    the month the financial year starts. The currency follows the jurisdiction until you change it.
    Every field has a real label, and errors are shown per field.
  - `/e/:entityId/<task>`: the current entity is in the URL, and in context for the pages.
- **Entity page load:**
  - It loads the entity, your role (your own active `entity_members` row) and your entity list.
  - "Not found" and "not a member" look the same on purpose.
  - A malformed id never reaches the database.
  - On any error, no entity page renders.
- **Switcher:** the header chip shows name, jurisdiction and currency. Its menu lists your entities
  (switching keeps you on the same task), "All entities" and "Create entity".

### Shell (`src/app/shell/`, `src/design/shell.css`)

- **Sidebar:** "Klaro / by Ledgrly", then Tasks (Plan, Compare, Cash, Report) and Setup (Connect).
  The footer shows your email and Sign out.
- **Top bar:** page title and summary, a "Go to… Ctrl K" button, the entity chip and your role.
- **KPI strip skeleton** on the four task pages: four tiles showing "—" and "No actuals yet".
  - It never shows a 0 that could be read as a real figure.
  - **The four labels (revenue YTD, gross margin, cash balance, cash runway) are placeholders: your
    call.**
- **Pages:**
  - Plan has an empty Drivers panel and chart area.
  - Compare, Cash and Report are empty states that say what each needs first, with links.
  - Connect lists three cards (accounting package, MCP-style connection, CSV import). Each has a
    disabled "Connect" button and says "Not available yet".
- **Command palette (Ctrl/Cmd+K):**
  - It covers the current entity's five pages plus "All entities". It searches no data.
  - Keys: arrows, Enter and Escape. Focus stays in the dialog and returns on close.
- **Errors:**
  - An error boundary wraps each page, reset on navigation.
  - The 404 page works inside and outside an entity.
- **Look:** dark Ledgrly design. The shell CSS is copied from Ledgrly `App.jsx` with the alias fixes
  listed in `src/design/PROVENANCE.md`.
- **Accessibility:** visible focus rings, 44px targets, real labels. Under 820px wide the sidebar
  turns into a top row.

### B. `npm run dev` with real settings: shows only the fail-closed page

`.env.local` holds public values only, and it is gitignored:
- the shared instance's publishable key, which encodes `clerk.ledgrly.ie`;
- the Supabase URL;
- the anon key.

With those, `http://localhost:5179` shows **"Klaro cannot start: Sign-in could not start on
localhost:5179…"**. This is correct. The shared production instance refuses localhost, and I
checked how:
- Clerk's error: `Production Keys are only allowed for domain "ledgrly.ie"`.
- Read-only requests to Clerk's Frontend API with different `Origin` headers:

  | Origin | Result |
  |---|---|
  | `https://klaro.ledgrly.ie` | **200** |
  | `https://klaro-local.ledgrly.ie` (no port) | **200** |
  | `http://localhost:5179` | **400** `origin_invalid` |
  | `https://klaro-local.ledgrly.ie:5179` | **400** `origin_invalid` |
  | `http://klaro-local.ledgrly.ie` | **400** `origin_invalid` |

So only https on a `ledgrly.ie` name, on the default port, works.

### C. `npm run dev:ledgrly`: real sign-in on this machine, if you want it (NOT verified)

This needs three things only you can do:
1. Add `127.0.0.1 klaro-local.ledgrly.ie` to the Windows hosts file. This is a system setting, so I
   didn't touch it.
2. Make a certificate for that name, for example with `mkcert klaro-local.ledgrly.ie`.
3. In `.env.local`, set `KLARO_DEV_HOST=klaro-local.ledgrly.ie`, `KLARO_DEV_CERT` and
   `KLARO_DEV_KEY` (the paths to the two certificate files).

Then `npm run dev:ledgrly` serves https://klaro-local.ledgrly.ie on port 443.

I checked that it refuses to start without those settings. I could not check that sign-in completes
this way: Clerk's session cookies on a hand-made host are the open question. If you'd rather not, B5's
preview is the real test.

## Settings to change before B5

### Clerk (dashboard; I changed nothing)

1. **Invitations.**
   - The instance is invite-only. An invitation without a redirect sends the person to the
     instance's default sign-up (the Account Portal), then to **app.ledgrly.ie**, where Ledgrly's
     create-company wizard appears.
   - Invite each Klaro pilot user with the invitation's redirect URL set to
     `https://klaro.ledgrly.ie/sign-up` (or the preview hostname's `/sign-up` for B5 testers).
   - Klaro's `/sign-up` page reads the invitation itself.
2. **Domains.**
   - The Frontend API already accepts `https://klaro.ledgrly.ie` and any other `https://<name>.ledgrly.ie`
     on the default port (the table above).
   - So a preview hostname such as `klaro-preview.ledgrly.ie` should need no Clerk change. Please
     still confirm in the dashboard that nothing (allowed origins, redirect allowlist) is limited to
     `app.ledgrly.ie`.
   - `*.vercel.app` URLs can never sign in.
3. **Known effects, no change needed unless you want one:**
   - Clerk's emails and hosted pages say "Ledgrly".
   - `single_session_mode` is on, so **signing out of Klaro signs the same browser out of Ledgrly**,
     and the other way round.

### Vercel (I changed nothing; deploys only through GitHub)
