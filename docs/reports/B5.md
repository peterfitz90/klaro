## Configuration problems found, and the guard added

The first deployments had two wrong Vercel values:
- **`VITE_CLERK_PUBLISHABLE_KEY`** was a development key (`pk_test_`, `valid-unicorn-80.clerk.accounts.dev`,
  the instance in Ledgrly's local `.env`). The sign-in box said "Development mode", and Supabase
  refused its tokens (401).
- **`VITE_SUPABASE_URL`** was `https://ihrbvnpwdxdppsnqlsfb.supabase.co/rest/v1/`, so requests went to
  `/rest/v1/rest/v1/…`.

You fixed both for production. **Guard** (`src/lib/config.ts`, used by `vite.config.ts` and at start-up):
- A Vercel build now **fails** if the Clerk key is not `pk_live_`, if the Supabase URL has anything
  after the host, or if the anon key is a secret key.
- The app refuses to start on the same problems.
- I simulated a Vercel build both ways: with the old values it fails and names the variable; with the
  right ones it builds.
- 3 new tests; 56 in total.

That guard briefly broke demo mode, which used a placeholder key. The demo now uses fake values in
the correct format.
